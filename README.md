## Why Do You Need Agent Reach?

AI Agents can already write code, edit documents, and manage projects — but ask them to find something online, and things quickly fall apart:

* 📺 "Summarize this YouTube tutorial for me" → **Can't watch it**, no subtitles available
* 🐦 "Search Twitter and see what people think about this product" → **Can't search**, Twitter's API is paid
* 📖 "Check Reddit to see if anyone has encountered the same bug" → **403 Forbidden**, server IP blocked
* 📕 "Check the reviews of this product on Xiaohongshu" → **Can't access it**, login required
* 📺 "There's a technical video on Bilibili — summarize it for me" → **Can't retrieve it**, generic download tools are heavily blocked by Bilibili
* 🔍 "Search the web for the latest comparison of LLM frameworks" → **No good search option**, either paid or poor quality
* 🌐 "Read this webpage for me" → **Gets a pile of HTML tags**, instead of readable content
* 📦 "What is this GitHub repository about? What are people saying in the Issues?" → It works, but authentication and configuration are tedious
* 📡 "Subscribe to these RSS feeds and tell me when they update" → You have to install a library and write the code yourself

**None of these are particularly difficult — but setting them up yourself is painful.**

Every platform has its own obstacles: paid APIs, anti-bot protection, authentication requirements, and data-cleaning problems. You have to research each one, install tools, and configure everything manually. Even getting an Agent to read Twitter can take half a day.

**Agent Reach turns all of that into a single sentence:**

```text
Install Agent Reach for me: https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/install.md
```

Give that to your Agent, and within minutes it can read Twitter, search Reddit, watch YouTube, browse Xiaohongshu, and more.

**Already installed? Updating is just as simple:**

```text
Update Agent Reach for me: https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/update.md
```

> ⭐ **Star this project.** We continuously track platform changes and add new channels. You don't have to keep up — when a platform breaks an integration, we fix it; when a new channel becomes available, we add it.

## Quick Start

> ⚠️ **OpenClaw users: make sure exec permissions are enabled first**
>
> Agent Reach requires the Agent to execute shell commands (`pip install`, `mcporter`, `twitter`, etc.). If your OpenClaw uses the default `messaging` tool profile, the Agent will not be able to execute commands. **Enable exec permissions before installation:**
>
> ```bash
> openclaw config set tools.profile "coding"
> ```
>
> Or set the following in `~/.openclaw/openclaw.json`:
>
> ```json
> {
>   "tools": {
>     "profile": "coding"
>   }
> }
> ```
>
> Then restart the Gateway:
>
> ```bash
> openclaw gateway restart
> ```
>
> Start a new conversation afterward. Other platforms such as Claude Code, Cursor, and Windsurf are not affected by this requirement.

Copy this sentence to your AI Agent (Claude Code, OpenClaw, Cursor, etc.):

```text
Install Agent Reach for me: https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/install.md
```

That's it. The Agent handles the rest.

> 🔄 **Already installed?** Updating is just as simple:
>
> ```text
> Update Agent Reach for me: https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/update.md
> ```

> 🛡️ **Safe by default:** `agent-reach install` only checks the environment by default. It does not automatically install system packages or modify configuration:
>
> ```text
> Safely check and install Agent Reach for me: https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/install.md
> ```
>
> Only use `agent-reach install --system` when you explicitly authorize system modifications.

<details>
<summary>What does it do? (Click to expand)</summary>

1. **Install CLI tools** — Install the `agent-reach` command from this repository. It includes yt-dlp and feedparser. Do not install the unrelated package with the same name from PyPI.
2. **Check system prerequisites** — Check for Node.js, gh CLI, mcporter, and other required dependencies and provide installation instructions for anything missing.
3. **Install and configure with authorization** — Only when `--system` is explicitly provided will it install dependencies and connect Exa through MCP.
4. **Detect the environment** — Determine whether you are running on a local computer or a server and provide appropriate configuration recommendations.
5. **Register SKILL.md with authorization** — Only when `--system` is explicitly provided will it write skills into the Agent's skills directory. The default mode only checks and does not modify files.
6. **Ask whether you want more** — By default, only six zero-configuration channels are activated. Login-based platforms such as Xiaohongshu, Twitter, Reddit, Facebook, and Instagram are presented as optional integrations. The Agent asks which ones you want to enable.

## Works Out of the Box

No configuration required. Just tell your Agent what you want:

* "Read this URL for me" → `curl https://r.jina.ai/URL`
* "What is this GitHub repository about?" → `gh repo view owner/repo`
* "What is this YouTube video about?" → `yt-dlp` extracts subtitles
* "Search Bilibili for AI tutorials" → `bili search` (no login required)
* "Search the web for LLM framework comparisons" → Exa semantic search
* "Subscribe to this RSS feed" → `feedparser`

**You don't need to remember any commands.** Once the Agent has read `SKILL.md`, it knows which tool to call.

For login-based platforms such as Xiaohongshu, Twitter, Reddit, Facebook, and Instagram, simply tell the Agent "Help me configure XXX" to unlock them.

## Design Philosophy

**Agent Reach is a capability layer, not another tool.**

It operates one level above the individual implementations. Its job is to **select, install, configure, health-check, and route** integrations. It does not implement the underlying data retrieval itself.

The Agent directly calls the upstream tools responsible for actual reading and searching. Agent Reach does not add another wrapper layer around them.

Whenever you set up a new Agent environment, you usually have to spend time finding the right tools, installing dependencies, and configuring authentication.

Which tool should you use for Twitter? How do you authenticate with Reddit? What should you switch to when a Xiaohongshu CLI becomes abandoned?

You have to solve these problems again for every new Agent.

Agent Reach keeps it simple:

**We select, install, and health-check the most reliable integration available today. When the integration changes, we update the route so you don't have to.**

### 🔌 Every Platform = Ordered Primary + Fallback Backends

Changing an integration means changing the order of the backend list — not rewriting the application.

`agent-reach doctor` tells you which backend is currently being used for each platform.

```text
channels/
├── web.py          → Jina Reader
├── twitter.py      → twitter-cli ▸ OpenCLI ▸ bird
├── youtube.py      → yt-dlp
├── github.py       → gh CLI
├── bilibili.py     → bili-cli ▸ OpenCLI ▸ Search API
├── reddit.py       → OpenCLI ▸ rdt-cli
├── facebook.py     → OpenCLI
├── instagram.py    → OpenCLI
├── xiaohongshu.py  → OpenCLI ▸ xiaohongshu-mcp ▸ xhs-cli
├── linkedin.py     → mcp-server-linkedin ▸ Jina Reader
├── rss.py          → feedparser
├── exa_search.py   → Exa via mcporter
└── __init__.py     → Channel registry (used by doctor)
```

Each channel performs a **real availability check** against its candidate backends rather than simply checking whether a command exists.

The first fully functional backend becomes the active one. Failed backends provide repair instructions.

The Agent performs the actual reading and searching directly through the selected upstream tool.

## Security

Agent Reach is designed with security in mind:

| Measure                         | Description                                                                                                                                                          |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 🔒 **Local Credential Storage** | Cookies and tokens are stored only on your local machine in `~/.agent-reach/config.yaml`, with file permissions set to 600 so only the owner can read or write them. |
| 🛡️ **Safe by Default**         | `agent-reach install` does not modify the system by default. External tools and configuration are only installed or modified when `--system` is explicitly provided. |
| 👀 **Fully Open Source**        | The code is transparent and can be audited at any time. All dependency tools are also open source projects.                                                          |
| 🔍 **Dry Run**                  | `agent-reach install --dry-run` previews all operations without making changes.                                                                                      |
| 🧩 **Pluggable Architecture**   | Don't trust a particular component? Replace the corresponding channel implementation without affecting the rest of the system.                                       |

### 🍪 Cookie Security Recommendations

> ⚠️ **Account suspension risk:** Using cookies to authenticate with platforms such as Twitter or Xiaohongshu and then accessing them through scripts/APIs may trigger platform detection and result in account restrictions or suspension. We strongly recommend using a **dedicated secondary account** rather than your primary account.

Platforms requiring cookies or browser sessions — including Twitter, Xiaohongshu, Reddit, Facebook, and Instagram — should ideally be accessed using a dedicated secondary account.

There are two main reasons:

1. **Account suspension risk** — Platforms may detect non-standard browser or API behavior and restrict or suspend the account.
2. **Security risk** — A cookie can provide access equivalent to an authenticated session. Using a secondary account limits the potential impact if credentials are compromised.

## 📦 Installation

| Method                       | Command                                    | Best For                                                                   |
| ---------------------------- | ------------------------------------------ | -------------------------------------------------------------------------- |
| Default safe check           | `agent-reach install --env=auto`           | All environments; performs read-only checks and lists missing dependencies |
| Explicit system installation | `agent-reach install --env=auto --system`  | When you explicitly authorize changes to the current machine               |
| Compatibility safe mode      | `agent-reach install --env=auto --safe`    | Same behavior as the default safe mode                                     |
| Preview only                 | `agent-reach install --env=auto --dry-run` | See what will happen before making any changes                             |

## 🗑️ Uninstall

```bash
agent-reach uninstall
```

This removes:

* `~/.agent-reach/` including all tokens and cookies
* Agent skill files
* MCP configuration registered in mcporter

```bash
# Preview without actually deleting anything
agent-reach uninstall --dry-run

# Remove only skill files while keeping token configuration
agent-reach uninstall --keep-config
```

To uninstall the Python package itself:

```bash
pip uninstall agent-reach
```
